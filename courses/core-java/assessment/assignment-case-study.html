Case Study 1 — Student Marks and Result Management System

Scenario

A college wants to develop a simple Java application to store and analyze the academic performance of students. The application should accept student information and marks in different subjects and generate a result summary.

Task

Develop a Java program that:

  1. Accepts the student's roll number, name, and marks in five subjects.
  2. Stores the marks using an appropriate data structure.
  3. Calculates:
    • Total marks
    • Average marks
    • Percentage
  4. Determines the student's result based on the percentage.
  5. Displays the student's complete result.
  6. Demonstrates the use of:
    • Variables and data types
    • final variable
    • One-dimensional array
    • Two-dimensional array, if appropriate
    • Comments
    • Basic Java class and main() method

Case Study 2 — Library Book Management System

Scenario

A college library wants to maintain information about books and students who borrow them. An object-oriented Java program is required to represent books and perform basic library operations.

Task

Design and implement a Java application that:

  1. Creates a Book class containing suitable fields such as:
    • Book ID
    • Book title
    • Author
    • Price
    • Availability
  2. Defines suitable constructors to initialize book objects.
  3. Demonstrates constructor overloading.
  4. Uses the this keyword appropriately.
  5. Creates an array of Book objects to store multiple books.
  6. Uses appropriate access specifiers (private, public, etc.).
  7. Overrides and demonstrates the toString() method to display book information.
  8. Demonstrates at least one suitable method from the Object class, such as equals() or getClass().
  9. Displays the details of all available books.

Case Study 3 — Employee Payroll System Using Inheritance and Interfaces

Related Unit

Unit 3 – Inheritance and Interface

Scenario

An organization has different types of employees, such as Permanent Employees and Contract Employees. Although all employees have common information, their salary calculations are different.

An object-oriented Java solution using inheritance and interfaces is required.

Task

Develop a Java application that:

  1. Create a superclass Employee containing common information such as:
    • Employee ID
    • Name
    • Basic salary
  2. Create suitable subclasses such as:
    • PermanentEmployee
    • ContractEmployee
  3. Use the extends keyword to implement inheritance.
  4. Use the super keyword where appropriate.
  5. Override a method such as calculateSalary() in the subclasses.
  6. Demonstrate runtime polymorphism using an appropriate superclass reference.
  7. Create an interface such as Payable containing a suitable method.
  8. Implement the interface in the required classes.
  9. Demonstrate the use of an abstract class and/or abstract method, where appropriate.
  10. Display the salary details of different types of employees.

Case Study 4 — Banking Transaction System with Exception Handling

Scenario

A bank wants to develop a simple Java application for performing basic account transactions. The system must prevent invalid operations such as withdrawing more money than the available balance or entering an invalid amount.

Task

Develop a Java program that:

  1. Creates a BankAccount class containing:
    • Account number
    • Account holder name
    • Balance
  2. Provides methods for:
    • Deposit
    • Withdrawal
    • Balance enquiry
  3. Handles the following situations:
    • Withdrawal amount greater than available balance
    • Negative deposit amount
    • Negative withdrawal amount
    • Invalid numerical input
  4. Uses appropriate try-catch blocks for exception handling.
  5. Demonstrates the difference between checked and unchecked exceptions through suitable examples.
  6. Creates and uses a user-defined exception, such as: 
    InsufficientBalanceException
  7. Uses finally to demonstrate a clean-up action or final message.
  8. Displays appropriate error messages instead of terminating the program unexpectedly.
